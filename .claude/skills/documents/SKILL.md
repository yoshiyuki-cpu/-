# 書類・ファイルを作るとき

「PDFにして」と言われたとき、答えは2通りある。**どちらかを先に決める。**

| | アプリの機能にする | その場でファイルを作る |
|---|---|---|
| 向いている | 毎月・毎週くり返し出すもの | 1回きり、社外向け、体裁を試したいもの |
| 例 | 見積書、請求書、会計CSV、給料明細 | 銀行に出す資料、事務所への説明用、たたき台 |
| 作り方 | 画面に出力ボタンを付ける | `pdf` / `xlsx` / `docx` スキルで作って渡す |

**判断の基準：3回以上出すならアプリに入れる。** 毎回Claudeに頼む形は、頼む人がいないと止まる。
仕組み化の考え方（`shikumika`）と同じで、人に依存する手順は仕組みではない。

## 標準で使えるスキル

ファイルそのものを作る・読む部分は、Claudeに最初から入っている次のスキルが自動で使われる。
このリポジトリに置く必要はない。

- **`pdf`** — PDFを読む・作る・結合する・分割する・スキャンした紙をOCRして検索できるようにする
- **`xlsx`** — Excel（.xlsx）とCSVを読む・作る・計算式や書式を入れる・散らかった表を整える
- **`docx`** — Word（.docx）を読む・作る・差し替える。報告書や案内文の体裁を整える

「先月のレシートをまとめてエクセルにして」「この請求書PDFの金額を拾って」のような依頼は、
そのまま頼めば動く。**元のファイルはこちらに渡してもらう必要がある**（クラウドの共有だけでは読めない）。

## アプリの中でPDFを出すとき

良心アプリの見積書（`app/estimates/[id]/print/page.tsx`）が実例。ブラウザの中で作っている。

- `window.print()` ＋ CSS（`no-print` / `print-page-break`）で印刷用の体裁を作るのが一番軽い
- ファイルとして残す必要があるときだけ `jspdf` を使う。読み込みは `import()` で必要になってから
- **html2canvas ではなく html2canvas-pro を使う。** Tailwind v4 の `oklch()` 色を通常版が解釈できず落ちる
- A4想定、金額は3桁区切り、社判・ロゴは画像として持つ

## 日本語の書類でつまずくところ

- **文字コード**：会計ソフト向けCSVは Shift_JIS 指定のことが多い。絵文字や一部の記号は
  「?」に化けるので、出す前に検出して止める（ケリーの仕訳CSVがこの作りになっている）
- **Excelで開くCSV**：UTF-8で出すならBOMを付けないと文字化けする
- **PDFの日本語**：フォントを埋め込まないと文字が消える。画像化して貼る方法なら確実
- **金額**：3桁区切り＋「円」。小数を出さない。端数の丸め方は書類の種類ごとに揃える
- **日付**：和暦が要るのは役所向けの書類だけ。ふだんは `2026/8/29(土)` の形

## 渡し方

作ったファイルは、置き場所を伝えるだけでなく**その場で送る**こと。
中身の要点（何件・合計いくら・どの期間か）を3行で添えると、開く前に確認できる。
