# 仕組み化の型

これは3つのアプリ（焼肉がみや／株式会社良心／ラウンジケリー）に共通する、オーナーの考え方の説明書。
機能を作る前にここを読むと、聞くべきことと作る量を外さない。

**共通する狙いは「その人がいなくても、同じ品質で回ること」。**
社長の頭の中にある段取りを、アプリに移し替えて、誰でも同じ手順を踏めるようにするのが全部の仕事の目的。
だから「便利なツール」より「毎日必ず使われる1画面」の方が価値が高い。

## 仕組みは5点セットで初めて回る

どれか1つでも欠けると、1週間で使われなくなる。新しい依頼を受けたら、5つ全部を確認する。

| # | 要素 | 3店での実例 |
|---|---|---|
| 1 | **決め事を1つに決める** | 開店前チェック項目／段取りは前日18:30までに決める／伝票は当日中に入力 |
| 2 | **記録する場所** | チェック表・段取り画面・伝票入力。紙とLINEから移す先 |
| 3 | **思い出す仕掛け** | LINEリマインド（報告業務16時・X投稿17:30・段取り18:30・朝の職長便） |
| 4 | **守れたかが見える** | 達成者の集計、来客評価、日次集計、利用状況の自動分析 |
| 5 | **見直して減らす** | 使われなかった仕込みタイマー・来客チェックは削除した |

依頼が「記録する場所」だけのときは、③と④をこちらから提案する。逆に③だけ足しても、
記録する場所が無ければ人は動けない。

## 相談を受けたら、まずこの3つだけ聞く

長い要件確認はしない。現場は忙しいので、次の3つが決まれば作り始められる。

1. **誰が、いつ、どこで触るか**（開店前の厨房／現場に向かう車の中／閉店後のカウンター）
2. **その人は何を見て動くか**（LINEが鳴る／出勤したらまず開く／伝票を書いた直後）
3. **できていないことが、どうなったら分かるか**（一覧に赤で出る／集計に名前が出る／通知が来る）

分からないところは仮で置いて作り、実物を見せて直す方が早い。使う人の言葉で確認すること。

## 現場で使われる形の基準

作ったものがこの基準を外していたら、機能として正しくても失敗する。

- **入力は3タップ以内。** 片手で、手袋のまま、暗い店内でも押せる大きさ
- **写真とAIで手入力を減らす。** レシート・手書き伝票・音声。ただし読み取れなくても手入力で必ず進める
- **間違えたら直せる。** 後から名前も金額も直せること（消せる、ではなく直せる）
- **記録は消さない。** 使わなくなった人・現場・商品は削除ではなく「表示しない印」で隠す。
  過去の台帳が壊れると信用がなくなる
- **その店の言葉を使う。** 卓・同伴・伝票／段取り・出面・人工・職長／仕込み・報告業務。
  システム用語（レコード、エラー、同期）は画面に出さない

## 作る量の決め方

- 初回は**画面1つ＋通知1本**まで。使ってもらってから足す
- 「あったら便利」は作らない。**毎日または毎営業日使うもの**だけ最初に作る
- 使われなくなったら消す。消すのも仕事（実際に仕込みタイマー・来客チェックは消している）

## 3店の性格の違い

同じ作り方でも、外してはいけない前提が店ごとに違う。

| | 焼肉がみや | 株式会社良心 | ラウンジケリー |
|---|---|---|---|
| 使う人 | ホール・厨房スタッフ | 職長・作業員 | キャスト・店長 |
| 端末 | 店のスマホ、営業中の合間 | 屋外・車内、電波が弱い | 深夜、暗い店内 |
| 日付の区切り | 朝5時で営業日が変わる | 暦日 | 深夜0時をまたぐので端末の日付 |
| 通知 | LINE公式（友だち全員） | LINE個別＋メール＋プッシュ | 通知より当日の入力導線 |
| 一番痛い失敗 | 開店に間に合わない | 台帳・段取りが消える | 売上と給料の計算が合わない |

## 関連スキル

- LINEで知らせるとき → `line-notify`
- 出す前の確認 → `release-check`
- 良心リポジトリでの実装 → `add-feature` / `ui-style` / `ai-analysis` / `notifications`
