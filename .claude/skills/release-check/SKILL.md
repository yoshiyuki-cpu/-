# 出す前の自己点検

3つのアプリの履歴には「動作確認で見つかった不具合を直した」「レビューで見つかった9件を修正」
「写真が貼れない問題を修正」「集合場所が正しく入力できない不具合を修正」といったコミットが並んでいる。
**作った直後の10分をここに使えば、その大半は出す前に潰せる。**

使うのは営業中の店・現場・深夜のカウンター。壊れたまま出すと、その日の業務が止まる。

## 1. 機械でできることを先に

```bash
npm run lint            # node_modules が無ければ先に npm install
npx tsc --noEmit        # 型の崩れを拾う（設定があるリポジトリのみ）
```

`npm run build` は Supabase などの環境変数が要るので手元で通らないことがある。
ただし**環境変数が無いだけでビルドが落ちる書き方はしない**（がみやは placeholder 値を入れて回避している）。

必要なら `/code-review` を自分の差分に対して走らせる。

## 2. 自分の差分を、敵の目でもう一度読む

「動くはず」ではなく「どこで壊れるか」を探す。過去に実際にやられた順:

- **今回追加した列でDB側の絞り込みをしていないか**（SQL未実行だと一覧が全部空になる → `supabase-migration`）
- **日付のズレ**。`toISOString()` はUTC。深夜0〜9時に使うと前日になる。営業日の区切りは店ごとに違う
  （がみや朝5時／良心 暦日／ケリー 端末のローカル日付）
- **保存されない入力**。フォームの項目を足したとき、`insert`/`update` の対象に入れ忘れていないか。
  選択なしの行が黙って捨てられていないか
- **写真・音声**。縮小しているか、読み取れなかったときに手入力へ逃げられるか、失敗メッセージが出るか
- **二度押し**。保存・送信・AI呼び出し中にボタンを止めているか
- **空のとき・初回のとき**。データが1件も無い画面が真っ白になっていないか
- **既存データとの混線**。過去の記録の表示や集計が変わっていないか（金額・人工・給与に直結）

## 3. 使う人の手つきで確認する

「コードが意図どおり動くか」だけを見ても、ここは落ちる。**社長が指で触ったときどうか**を見る。
実際に何度も指摘されたのはこの4つで、いずれも金額や保存は正しかった。

- **開いた直後、スクロールなしで何が見えているか**。頼まれた物が画面の外に出ていないか。
  要素の座標を実測して確かめる（下タブの60pxを引いた範囲に入っているか）
  → 日別の費用で、頼まれた現場ごとの内訳が月カレンダーの下に隠れていた
- **2回目・3回目に開いたときの流れ**。毎回同じ入力をやり直させていないか。
  合言葉・選択・絞り込みを端末に覚えさせるべきでないか
  → 振り返りで、開くたびに合言葉を打たせていた
- **キーボードの種類**。`inputMode="numeric"` を数字以外の欄に付けていないか。
  スマホでは文字が打てなくなる（PCのブラウザでは気づけない）
  → 合言葉の欄に付けてしまい、英字も日本語も打てなかった
- **同じ画面に同種の入力欄を2つ以上出していないか**。どちらに入れるのか分からなくなる
  → 振り返りの入口に、職長用と管理者用の合言葉の欄を並べていた

そのうえで:

- **スマホ幅（375px）**で見る。下のタブバーに隠れていないか、押せる大きさか
- 実際の動線を最初から最後まで1回通す。「開く → 入力 → 保存 → 一覧に出る → 直す」。
  **1回で終わらせず、閉じてもう一度開く**
- **頼まれていない物を足していないか**。親切のつもりの選択肢が邪魔になる
  → 管路図に種別ボタンを勝手に付け、外すことになった
- 通知を変えたなら、テスト送信で**実物の文面**を見る（良心はマスタ画面のテスト送信ボタン）
- 画面に出る日本語を読み返す。システム用語が漏れていないか、失敗メッセージが
  「次にすること」になっているか

## 4. コミットとpush

- コミットメッセージは日本語一行で「〜できるようにした」「〜を追加」「〜の不具合を修正」。
  本文に**なぜ必要だったか**を数行（履歴が仕組みの記録になる）
- ブランチは指定されたものに push する

## 5. 報告の型

オーナーは全部のコードを読まない。次の形で短く返す:

```
変えたこと
- （3行まで、業務の言葉で）

確認してほしいこと
1. （実際に押してほしい画面と操作）
2.
3.

Supabaseで実行が必要なSQL
- supabase-schema-xxx.sql（実行するまで新機能だけ使えません。既存のデータは消えません）

気になっている点
- （残した懸念があれば正直に。無ければ書かない）
```

**できていないことを黙って出さない。** 途中まででも「ここまでできた・ここが残っている」と
書いた方が、後から不具合として出てくるより早い。
